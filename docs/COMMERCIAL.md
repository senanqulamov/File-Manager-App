# Bring Docket into your document workflow

Docket is intended for teams that want a desktop workspace for company documents while operating their own server and storage. Engineering, construction, project administration, and office teams can evaluate it against their own document-handling needs.

## Start with a demonstration

[**Request a demo or commercial discussion →**](https://github.com/senanqulamov/File-Manager-App/issues/new?template=demo-request.yml)

The enquiry form is public. Share only a high-level description of your use case. Do not include confidential documents, passwords, internal server addresses, personal contact details, or procurement information. Request a private follow-up channel before exchanging those details.

The maintainer is [Senan Qulamov](https://github.com/senanqulamov). There is no automated checkout or published price list in this repository.

## What we can discuss

| Discussion | What to establish |
| --- | --- |
| Product demonstration | Which workflows matter: browsing, versions, sharing, document tools, or administration |
| Controlled evaluation | Sample documents, pilot users, environment, acceptance criteria, and evaluation permission |
| Deployment scope | Server ownership, network access, storage, backups, desktop installation, and optional tools |
| Commercial licence | Permitted use, organisations/users covered, duration, and distribution rights |
| Source-code access | Whether source delivery or modification rights are included in a written agreement |
| Support and maintenance | Contact channel, supported versions, update scope, and response expectations |

Pricing, support commitments, branding work, installation services, and source-code rights must be agreed in writing. They are not included merely because source code is publicly visible.

## A useful first evaluation

1. Select a representative workflow and non-confidential sample documents.
2. Walk through it with one user account and one administrator account.
3. Record format requirements, access rules, editing applications, and deployment constraints.
4. Agree the fixes and acceptance tests needed before introducing real company documents.
5. Confirm commercial terms and operational ownership before deployment.
