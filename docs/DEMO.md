# A five-minute Docket demonstration

Use the [local sample environment](QUICKSTART.md) and disposable documents. Rehearse the exact build before presenting. Show the running application; label any design reference shown separately.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:45 | Sign in as `a.karimova`; open My files and Company | One desktop workspace for personal and company documents |
| 0:45–1:30 | Browse, filter, select a PDF, and open its preview | Familiar navigation with document actions close to the file |
| 1:30–2:30 | Check out a prepared sample, edit/save it, check in with a comment | A deliberate editing workflow with version history |
| 2:30–3:15 | Inspect versions; share a sample with `t.mammadli` | Earlier work remains accessible and sharing has an explicit recipient |
| 3:15–4:15 | Switch to `r.aliyev`; show users, permissions, and audit records | IT has a central place to administer the workspace |
| 4:15–5:00 | Discuss the prospect's workflow | Agree which formats, access rules, and deployment needs a pilot must prove |

For document tools, prepare a separate optional example with the required server tools installed. Demonstrate signing as a PDF feature and explain the certificate-trust limitation. Never use a visual stamp as evidence of an approval workflow.

## Close with a concrete next step

Ask which single workflow the prospect would evaluate first. Agree sample data, pilot roles, success criteria, and a private follow-up channel. Describe the current pre-release stage and open validation work from [status](STATUS.md). Discuss commercial scope using the [enquiry guide](COMMERCIAL.md); do not improvise prices or service guarantees.
